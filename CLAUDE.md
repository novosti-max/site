# Бот «Радар»: MAX → ВКонтакте (ветка `radar-bot`)

Проект сети «Андрей + Никита». Бот переносит посты MAX-каналов «Радар» в группы ВК.
Ветка `main` этого репозитория — сайт novosti-max.com, отдельный проект «Илья + Никита». Его **не трогать**.

## Правила владельца (Никита)
- Ничего не удалять, не менять сервер и не пушить в GitHub без явного «да» Никиты. Исключение: правки бота, которые он уже одобрил в разговоре.
- Пароли, токены, ключи и секретную ссылку страницы настройки не просить в чат, не писать в репозиторий и в журналы.
- Доступ к MAX не запрашивать. Ограничения ВК не обходить.
- Посты в ВК удалять только с согласия Никиты.
- Отвечать по-русски, коротко.

## Как устроено
- `radar_bot.py`: основной цикл. Читает события MAX, `handle()` разбирает пост и публикует его в группы ВК ключами групп. Также делает пост-перелив в 20:00, пост «перешлите», `apply_fixes()` при запуске.
- `textproc.py`: разбор текста: реклама, тип (danger / clear / attention / quiet / topic / news), чистка, регион, карточки, OCR плашек, заголовок новости.
- `vkid.py`: вход админа через VK ID и загрузка фото на стену его ключом.
- `setup_server.py`: страница настройки (токен MAX, ключи групп, режим, вход VK ID) на `https://novosti-max.com:8443/<секрет>/`. В репозитории лежит только хэш секрета (`setup_key.sha256`).
- `config.yaml`: боевой конфиг. У групп есть `city`, `source`, `vk`, `gid` и 8 карточек (danger, clear, missile, missile_clear, mvsh, mvsh_clear, attention, share). Включены 13 групп; ufa, kursk, chuvashiya, bryansk, tula, krasnodar выключены (`enabled: false`). В `rules` стоит `post_news: true`.
- `fixes.yaml`: очередь исправлений уже вышедших постов (см. ниже).
- `tools/replay.py`: проверка нового правила на настоящих постах MAX (см. «Как менять правила»). `shadow/` — пробный режим.
- Журнал постов: бот после обработки каждого поста MAX своих каналов дописывает его в `/var/lib/radar-bot/corpus.jsonl` (последние 1500): текст, вложения, что вышло во ВК, что показал OCR. Пишется уже после публикации — тревоги не задерживает; ошибка записи публикацию не ломает.
- Сервер REG.RU: `/opt/radar-bot`, сервисы `radar-bot` и `radar-setup` (пользователь radarbot). Секреты лежат в `/etc/radar-bot/secrets.json`, состояние и журнал — в `/var/lib/radar-bot/` (state.json, bot.log, vkid.json).
- **Выкладка:** `deploy/radar-bot-hook.sh` (из `main`, вызывается раз в минуту) видит новый коммит в `radar-bot`, делает `reset --hard` и запускает `deploy/install.sh`, тот перезапускает сервисы. Коммит попадает на сервер за 1–2 минуты.
- **Проверка снаружи:** https://novosti-max.com/.well-known/acme-challenge/rb-status.txt — коммит, состояние сервисов, строка «с запуска …: опубликовано N, пропусков N, ошибок N, предупреждений N; в журнале постов: N», последние 60 строк журнала, журнал установки. Ключей там нет. Отчёт пробного режима — `rb-shadow.txt` там же. Если файл не обновляется (так было с 11:20 01.11), смотреть журнал на странице настройки.

## Правила постов (решения Никиты, 31.10–01.11)
- **Карточка только в начале тревоги.** «Опасность БПЛА» с карточкой ставится на первый пост, дальше до отбоя посты идут без неё. Ракеты, МВШ и «Внимание» получают свои карточки, тоже только в начале. Отбой: одна зелёная карточка. Новая серия начинается после отбоя или после 6 ч тишины (`series_reset_hours`). Реализация — `card_decision()`.
- «Сохраняется / продолжается» — без карточки. Памятки и новости о налёте («ВСУ атаковали…», «по словам губернатора») — тоже без карточки.
- «безопасности» не считается «опасностью» (FIX-1).
- **Что идёт в региональную группу** (FIX-3/17/18/19/20, решения Никиты 01.11). Группа «Россия» получает всё.
  - Свой регион (`REGION_WORDS`, проверка по тексту без подписи канала) — как есть.
  - Новости о налётах на Россию из других регионов (НПЗ Кстово, «сбито N БПЛА над областями») — как есть, без карточки.
  - Зарубежье/Украина, политика, СВО — с рубрикой в первой строке «🌍 МИР | », «🏛 ПОЛИТИКА | », «⚔️ СВО | », без карточки, не больше `rules.rubric_per_day` (5) в сутки на группу и ни одной, пока в регионе тревога (`rubric_alert_pause_min`, 90 мин после последнего оповещения без отбоя).
  - Оповещения других регионов и прочие чужие новости (без налёта и без рубрики) — не идут.
  - Политика со своим городом («пусть приезжает в Москву») — тоже рубрика, не «своя» новость.
- «🔴Регион» / «✅ Регион» → бот дописывает «Опасность по БПЛА» / «Отбой опасности по БПЛА» (FIX-6). Дописывает только к посту, где есть лишь название места (FIX-11).
- Пост «Регион» + картинка-плашка MAX → бот читает плашку через OCR (tesseract rus), дописывает текст и ставит НАШУ карточку. Если не распознал, пропускает и пишет в журнал (FIX-10). Короткая новость с фото выходит как новость.
- **Фото новостей.** Фото, загруженные ключом группы, ВК на стене не показывает. Вход VK ID выполнен (Роман, VK id 556584144), но VK выдал только `vkid.personal_info`: в приложении «Радар постинг» (ID 54866180) нельзя включить фото и стену. Решение Никиты: новости без фото. Наши карточки видны, потому что их заранее загрузили в группы.
- **Регион — по тексту без подписи канала (FIX-17).** У Рязани и Саратова каналы общие новостные, и подпись «Рязань… / Саратов… - Подписаться» раньше делала любую федеральную новость «своей» (01.11: «Путин… Зеленский», «атака на НПЗ Кстово»).
- **«Россия»: серия карточек у каждого региона своя (FIX-17, `series_key`).** 01.11 «🔴Северная часть Ростовской области» вышла без карточки из-за утренней серии по Смоленску.
- **Заголовок новости (FIX-16).** У поста без карточки первая строка — заголовок: в начале ⚡️, если значка нет, и пустая строка после. Жирный шрифт ВК боту не даёт.

## Как менять правила (решение Никиты 01.11: «чтоб при добавлении задач не упираться в посты с косяками»)
Скорость тревог это не трогает: проверки идут в стороне от бота.
1. **Тесты:** `bash tests_claude/run_tests.sh <репозиторий>` → «ВСЁ ПРОЙДЕНО». На каждую найденную ошибку — новый тест.
2. **Прогон на настоящих постах до выкладки:** изменённый файл кладётся в `shadow/` (боевой бот его не видит). Через 1–2 минуты в `rb-shadow.txt` отчёт: сколько постов из журнала вышло бы иначе и как («было … / стало …», по группам). Показать Никите короткий список, ❌-случаи исправить и прогнать снова. Строка «Прогон текущего кода совпал с тем, что реально вышло: X из Y» — проверка самого прогона; расхождения в первые часы журнала нормальны (состояние начинается с нуля).
3. **Пробный день** — для рискованных правил (что идёт в группы, карточки, лимиты): файл остаётся в `shadow/` сутки, отчёт обновляется каждые 30 минут на свежих постах. Потом смотрим отчёт с Никитой.
4. **Выкладка:** после «да» Никиты файл переносится в корень ветки, из `shadow/` удаляется.
5. **Проверка после выкладки:** через 30 минут и через 3 часа — `rb-status.txt` (коммит, «старт: 13 групп», нет Traceback, счётчики «с запуска») и стены групп. Claude ставит себе напоминания (send_later). Что не так — сразу Никите.
Локально: `python3 tools/replay.py --old <код> --new <папка с изменёнными файлами> --corpus corpus.jsonl`.

## Исправление вышедших постов: `fixes.yaml`
**Бот сам править и удалять посты НЕ может:** `wall.edit` и `wall.delete` ВК разрешает только с ключом пользователя, ключом группы — ошибка 27 (проверено 01.11 17:35). Исправления делает Claude вручную в браузере под админом (меню поста «…» → Редактировать / Удалить), а в `fixes.yaml` записывает, что исправлено, где и по чьему согласию. Код `apply_fixes()` оставлен: заработает, если появится ключ пользователя. Удаление — только с согласия Никиты.
